# SatQuery intent dataset and model (v1)

The local intent model maps a question to ONE operation label. It computes
nothing: places and dates are extracted by the deterministic reader
(`app/services/agent/interpretation.py`) and replaced by `PLACE` / `DATE`
before the model sees the text; the scientific pipeline is unchanged.

## Files

| File | What it is |
| --- | --- |
| `satquery_intents_v1.jsonl` | Training data: one `{"id", "text", "intent"}` per line, hand-written, 127-129 per label |
| `satquery_intents_v1_challenge.jsonl` | 120 questions (15 per label) written after every modelling choice was frozen; evaluated once, never used for any choice |
| `evaluation_v1.json` / `evaluation_v1.md` | Generated by the training script: metrics, confusion matrices, threshold calibration, every misclassification |
| `../../app/services/agent/intent_artifacts/satquery_intent_v1.json.gz` | The shipped model: gzip-compressed JSON (vocabularies, IDF, coefficients). Data, not code - no pickle |

## Labels

`NDVI`, `NDWI`, `NDBI`, `SAR_BACKSCATTER`, `TEMPORAL_NDWI` (water compared
between two periods), `TRUE_COLOR` (imagery only), `CLARIFICATION` (no
operation stated, including "compare X" with no subject) and `UNSUPPORTED`
(floods, temperature, disease, counting or detecting objects, classification,
volume or depth, and change in anything but water). Only what the backend
actually computes has a label.

## Regenerate

```sh
cd backend
uv sync                                   # scikit-learn is a dev dependency
uv run python scripts/train_intent_model.py
```

The same dataset and script produce the same artifact bytes (the SHA-256 is in
`evaluation_v1.json`). Production does not need scikit-learn: it reads the JSON
with numpy, and `tests/test_intent_model.py` checks that inference against
scikit-learn itself.

## Protocol, briefly

Split by family (near-duplicates and cross-label twins never straddle a
split), C chosen by grouped 5-fold CV on train, threshold chosen on
out-of-fold + validation predictions (lowest with >= 99% accepted precision),
test and the challenge set evaluated once. A confident prediction is acted on
only when it does not contradict an operation the rules read explicitly; see
`app/services/agent/intent_router.py` for the full decision rule.
