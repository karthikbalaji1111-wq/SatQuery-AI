# SatQuery intent dataset and model (v2)

The local intent model maps a question to ONE operation label. It computes
nothing: places and dates are extracted by the deterministic reader
(`app/services/agent/interpretation.py`) and replaced by `PLACE` / `DATE`
before the model sees the text; the scientific pipeline is unchanged.

## Files

| File | What it is |
| --- | --- |
| `satquery_intents_v2.jsonl` | Training data (shipped model): v1 unchanged plus ~30 new examples per label, 157-159 per label, 1,258 rows |
| `satquery_intents_v2_challenge.jsonl` | 120 questions (15 per label) written BEFORE any v2 training; the held-out measure for v2 |
| `evaluation_v2.json` / `evaluation_v2.md` | Generated by the training script: metrics, confusion matrices, threshold calibration, every misclassification, and v1 -> v2 on the same sets |
| `satquery_intents_v1.jsonl` | The v1 training data (a subset of v2), kept as the record of what v1 learned |
| `satquery_intents_v1_challenge.jsonl` | v1's challenge set. Its v1 misses were read and informed dataset v2, so for v2 it is DEVELOPMENT data and is reported as such |
| `evaluation_v1.json` / `evaluation_v1.md` | v1's report, kept as history; its artifact is no longer shipped |
| `../../app/services/agent/intent_artifacts/satquery_intent_v2.json.gz` | The shipped model: gzip-compressed JSON (vocabularies, IDF, coefficients). Data, not code - no pickle |

## Labels

`NDVI`, `NDWI`, `NDBI`, `SAR_BACKSCATTER`, `TEMPORAL_NDWI` (water compared
between two periods), `TRUE_COLOR` (imagery only), `CLARIFICATION` (no
operation stated, including "compare X" with no subject) and `UNSUPPORTED`
(floods, temperature, disease, counting or detecting objects, classification,
volume or depth, yield and forecasting, and change in anything but water).
Only what the backend actually computes has a label.

## What v2 added, and why

The v1 challenge misses clustered into phrasings the data did not cover:
vegetation as "leafy / lush / green / crop vigour / plant health", water as
"extent / surface water / spread", built-up as "concrete / developed /
impervious / urbanisation", SAR as "radar / backscatter / microwave", and
comparisons as "changed / rose / fell / before vs after / compared with /
from ... to". v2 adds diverse examples of each, plus hard negatives beside
them (a change in vegetation or built-up area is UNSUPPORTED; "compare" with
no subject is CLARIFICATION), so no unsupported meaning was added to raise a
score.

## Regenerate

```sh
cd backend
uv sync                                   # scikit-learn is a dev dependency
uv run python scripts/train_intent_model.py \
    [--baseline path/to/satquery_intent_v1.json.gz]
```

The same dataset and script produce the same artifact bytes (the SHA-256 is in
`evaluation_v2.json`). `--baseline` evaluates a previous artifact on the same
challenge sets, through today's rules, for the before -> after table; the v1
artifact is in git history (`git show b608996:backend/app/services/agent/intent_artifacts/satquery_intent_v1.json.gz`).
Production does not need scikit-learn: it reads the JSON with numpy, and
`tests/test_intent_model.py` checks that inference against scikit-learn itself.

## Protocol, briefly

Split by family (near-duplicates and cross-label twins never straddle a
split), C chosen by grouped 5-fold CV on train, threshold chosen on
out-of-fold + validation predictions (lowest with >= 99% accepted precision,
and never below 0.90), test and the challenge sets evaluated once. A
confident prediction is acted on only when it does not contradict an
operation the rules read explicitly; see `app/services/agent/intent_router.py`
for the full decision rule.

## Honesty notes

- The first v2 evaluation also exposed rule gaps (change verbs such as
  "declined" or "risen", yield / forecasting requests, "<place> looks like",
  names beginning like "my" / "it" / "here", "how leafy is"). Those rules were
  fixed and the model retrained on the SAME data with the same protocol. The
  challenge v2 numbers reported after that are therefore no longer fully
  blind for the items that exposed the gaps. The first, blind evaluation is
  recorded in `CLAUDE.md` section 26.
- 39 of the 120 challenge-v2 items are >= 0.75 similar (char 4-gram Jaccard,
  after masking) to some training sentence: short question skeletons recur.
  The report states this per set.
